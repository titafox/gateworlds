## 🌍 Gateworlds 是什么？

Gateworlds 是一个从零开始建设的开源游戏与社区实验。

我们的目标不是开发一款内容固定的游戏，而是创造一个由社区共同建设、不断扩展的开放世界宇宙。

在这里，你可以：

* 像生活模拟游戏一样生活、种田、钓鱼、建造家园。
* 创造一个修仙世界，建立宗门、炼丹、御剑飞行。
* 建设赛博朋克都市，探索人工智能与未来科技。
* 创造星际文明，探索宇宙。
* 设计全新的物理规则、社会系统和游戏机制。
* 创造一个我们今天还无法想象的世界。

这些只是例子，而不是游戏题材的限制。

**世界应该由创造者想象，而不是由项目创始人预先规定。**

我们希望每个人都能够借助 AI，把自己的想象变成真实、可玩的游戏内容。

## ✨ 核心理念

### 1. 人人都可以创造

你不需要成为专业程序员。

你可以提出创意、设计玩法、绘制地图、制作音乐、寻找 Bug，也可以利用 AI 编写代码。

从一句简单的描述开始：

> 我想创造一个修仙世界，里面有宗门、灵根、炼丹和渡劫。

通过 AI 辅助开发、模块化工具和社区协作，我们希望逐步把这样的创意变成真正可以运行的世界。

AI 降低创造的门槛。

社区让创造的成果得以延续。

### 2. 不限制世界观

Gateworlds 不会把所有世界限制在同一种玩法中。

一个世界可以拥有等级、战斗和魔法。

另一个世界可以完全没有战斗，只允许玩家种田和交朋友。

创作者可以为自己的世界定义独特规则。

不同世界之间可以通过共同协议互相连接，但不必拥有完全相同的玩法和经济系统。

### 3. 开源与共同建设

我们计划开放游戏代码、世界开发工具、相关协议和治理规则。

社区成员可以提出修改建议、提交代码、修复问题、开发新系统，并参与项目治理。

开源不意味着未经审核的代码可以直接进入正式游戏。

所有公开发布的代码和内容都应经过与风险相适应的审核、测试和许可检查。

### 4. AI 原生开发

AI 不仅用于生成游戏素材，也将参与软件开发的完整流程：

* 将自然语言创意转化为开发任务。
* 生成代码和测试。
* 辅助分析架构与兼容性。
* 检查潜在缺陷与安全风险。
* 生成技术文档。
* 协助世界之间的适配与迁移。

AI 是开发助手，不是拥有无限权限的管理者。

涉及核心架构、安全、玩家数据和正式发布的变更，需要遵循项目治理及审核流程。

### 5. 一切技术选择都可以被重新讨论

游戏引擎不是永久的。

SDK 不是永久的。

世界协议不是永久的。

甚至项目的治理宪法，也不是永久的。

只要按照当时有效的治理程序，社区就可以提出、审议并实施修改。

我们不会因为某项技术最先被使用，就要求所有未来的创造者永远服从它。

**工具应该服务于创造，而不是限制创造。**

## 🪐 一个宇宙，无数世界

Gateworlds 希望建立可扩展的世界体系。

```text
                  Gateworlds
                      |
               共享宇宙服务
                      |
       +--------------+--------------+
       |              |              |
    田园世界        修仙世界       赛博世界
       |              |              |
    社区内容        社区内容       社区内容

              +-------+
              |
          新世界……
```

不同世界可以拥有独立的规则、地图、存档和玩法。

共享宇宙服务则负责必要的身份、世界发现、传送及跨世界协作能力。

跨世界物品和能力必须遵守目标世界的规则。

例如，修仙世界中的飞剑可以在田园世界中作为装饰，但不应自动获得破坏其他玩家建筑的权限。

这些互通能力将逐步开发，而非第一版本就全部实现。

## 🛠️ World SDK：让任何人创造世界

我们计划开发 World SDK，让创作者能够以模块化的方式创建和接入新的世界。

SDK 将逐步提供：

* 世界注册与加载。
* 世界入口与传送。
* 世界独立数据与存档。
* 世界间通信。
* 资源及物品标识。
* 权限管理。
* 版本兼容和迁移。
* 自动化测试与发布流程。

SDK 本身也属于社区可以修改的项目组成部分。

如果现有 SDK 无法支持一种新玩法，社区可以提出扩展、修改乃至替换方案。

我们不会在最初阶段尝试设计一套所谓完美的通用 SDK。

第一阶段将通过实际开发多个小型世界，验证并逐步形成接口。

## 📜 Gateworlds 宪法

Gateworlds 希望逐步建立公开、透明、可修订的社区治理制度。

初始宪法草案将讨论以下原则：

**开放创造**

所有人都可以提出创意、开发方案和改进建议。

**公开治理**

影响整个公共宇宙的重要决定，应当遵循明确、可追溯的程序。

**技术可变更**

游戏引擎、SDK、核心协议和技术架构均可以通过适用程序修改。

**存量成果保护**

重大升级应考虑现有世界、玩家数据及贡献者成果，提供合理的兼容、迁移或回滚方案。

**宪法可修订**

社区可以依据当时有效的修宪程序修改宪法，包括修宪程序本身。

**独立派生**

项目应按照所采用的开源许可证，明确允许的修改、再发布和独立部署方式。

在社区治理体系尚未建立前，创始维护者将临时负责项目初始化、安全审核和版本发布。

这不是永久权力。

项目需要逐步建立清晰的成员资格、决策程序、权限移交和争议解决机制。

治理文件将单独维护：

[`CONSTITUTION.md`](CONSTITUTION.md)

当前宪法仍处于草案阶段，具体表决机制尚未确定。

## 🎮 第一个可玩版本

### Gateworlds 0.0.1

**这部分已经可以跑了。** `godot --path client-godot` —— 从村庄往东走进传送门，捡起灵草，再走回来。`I` 打开背包，`F5` 存档，`F9` 读档。见 [`docs/BOOTSTRAP.md`](docs/BOOTSTRAP.md)。

我们的首个开发目标是：

**一座村庄、一个修仙世界、一扇传送门。**

第一阶段计划实现：

* 玩家可以在初始村庄自由移动。
* 玩家可以通过传送门进入修仙世界。
* 玩家可以在修仙世界获得一株灵草。
* 玩家返回村庄后仍然保有该物品。
* 两个世界的数据可以正确加载和保存。
* 世界采用初步模块化结构。

在此基础上，我们将尝试让新的贡献者利用 AI 创建第三个世界，并在审核后接入游戏。

第一个版本不追求庞大的地图和复杂的内容。

它要证明的是：

**一个新世界能否被创造，并真正加入这个宇宙。**

初始原型可能采用 2D 和单机运行，以降低开发复杂度。这不构成对未来游戏维度、画面表现或联机能力的永久限制。

## 🤝 如何参与？

我们欢迎各种形式的贡献。

你可以：

**提出创意**

设计一个新世界、新玩法或新的宇宙规则。

**参与开发**

利用 AI 或传统编程方式提交代码。

**制作内容**

贡献符合授权要求的地图、建筑、美术、音乐和剧情。

**测试游戏**

寻找 Bug，反馈性能问题和游戏体验。

**改进架构**

提出 SDK、协议、服务器及开发工具的改进方案。

**参与治理**

讨论项目规则、提交宪法修改草案、参与正式建立后的社区治理。

从 [`CONTRIBUTING.md`](CONTRIBUTING.md) 开始。它很短，而且附了一个可以直接复制的完整世界。

涉及代码的贡献，应当通过 Pull Request 提交，并接受审核。

请不要直接将未经授权的第三方代码、游戏素材或个人隐私数据提交到项目中。

大量未经筛选的 AI 生成内容也不应直接进入正式分支。

贡献规范在 [`CONTRIBUTING.md`](CONTRIBUTING.md)，而关于规范本身的规范在 [`CONSTITUTION.md`](CONSTITUTION.md)。

## 🔒 安全与质量

开放创造不意味着开放无限权限。

项目计划采用多层审核机制：

1. 静态代码和依赖检查。
2. AI 辅助代码审查。
3. 自动化功能与兼容性测试。
4. 必要的人类维护者审核。
5. 隔离构建、测试和分阶段发布。

未经批准的外部代码，不应直接在正式游戏服务器上执行。

核心系统、玩家存档及敏感数据需要更严格的访问控制。

AI 审核不能替代全部安全检查。

对于存在较高风险的变更，我们将优先保护运行环境和玩家数据。

商业运营不应被用来暗中剥夺已授予社区的开源权利。

Gateworlds 致力于最大限度地开放创造、修改、分发和商业使用的自由。

* 游戏源代码、SDK 和开发工具：**0BSD License**

* 项目宪法与原创文档：**CC0 1.0 Universal**

第三方依赖及资源遵循其各自的许可证，不自动纳入上述授权范围。贡献者必须确保自己有权按相应许可提交内容。

任何人都可以在适用许可证允许的范围内使用、修改、分发、商业化或派生 Gateworlds。

我们鼓励自愿署名、回馈社区及公开改进成果，但不将其作为上述许可证的额外法律条件。

Gateworlds 的治理制度可以修改未来版本的授权安排，但不得据此撤销既有版本中已经有效授予的权利。

**创造属于每个人。**

详见 [`LICENSE`](LICENSE)（0BSD）与 [`LICENSE-CC0`](LICENSE-CC0)（CC0 1.0 Universal）。
