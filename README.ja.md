## 🌍 Gateworlds とは？

Gateworlds は、ゼロから立ち上げているオープンソースのゲーム／コミュニティ実験です。

目指しているのは、内容が固定された一本のゲームを出すことではありません。コミュニティが共同で築き、広げ続けていくオープンワールドの宇宙をつくることです。

ここでは、こんなことができます。

* 生活シミュレーションのように暮らし、畑を耕し、釣りをし、家を建てる。
* 仙道修行（修仙）の世界をつくる。宗門を興し、錬丹を行い、御剣飛行をする。
* サイバーパンク都市を築き、人工知能と未来技術を探究する。
* 星間文明を興し、宇宙を探索する。
* まったく新しい物理法則、社会システム、ゲームメカニクスを設計する。
* 今の私たちにはまだ想像もつかない世界をつくる。

これらはあくまで例であり、許されるジャンルの一覧ではありません。

**世界は、その創り手が想像するものであり、プロジェクトの創始者があらかじめ定めるものではありません。**

誰もが AI の力を借りて、自分の想像を実際に遊べるゲーム内容に変えられるようにしたいと考えています。

## ✨ 中核となる理念

### 1. 誰でも創れる

専門のプログラマーである必要はありません。

アイデアを出す、遊びを設計する、マップを描く、音楽をつくる、バグを見つける——AI を使ってコードを書くこともできます。

たった一文から始められます。

> 宗門と霊根と錬丹と天劫のある、修仙の世界をつくりたい。

AI 支援開発、モジュール化されたツール、コミュニティの協働を通じて、こうしたアイデアを実際に動く世界へと少しずつ変えていきたいと考えています。

AI は創造の敷居を下げます。

コミュニティは、創られたものを続かせます。

### 2. 世界観を限定しない

Gateworlds は、すべての世界を同じ一種類の遊び方に押し込めることはしません。

ある世界にはレベルと戦闘と魔法があってよい。

別の世界には戦闘が一切なく、畑を耕して友達をつくるだけでもよい。

創り手は自分の世界のルールを自分で定められます。

世界どうしは共通のプロトコルでつながることができますが、まったく同じメカニクスや経済システムを持つ必要はありません。

### 3. オープンソースと共同構築

ゲームのコード、世界開発ツール、関連プロトコル、ガバナンス規則を公開する計画です。

コミュニティのメンバーは、変更を提案し、コードを提出し、不具合を修正し、新しいシステムを開発し、プロジェクトの運営に参加できます。

オープンソースであることは、未レビューのコードがそのまま本番のゲームに入ることを意味しません。

公開されるすべてのコードとコンテンツは、そのリスクに見合ったレビュー・テスト・ライセンス確認を通す必要があります。

### 4. AI ネイティブな開発

AI は素材生成だけでなく、ソフトウェア開発の全工程に関わります。

* 自然言語のアイデアを開発タスクに変換する。
* コードとテストを生成する。
* アーキテクチャと互換性の分析を支援する。
* 潜在的な欠陥とセキュリティリスクを検査する。
* 技術文書を生成する。
* 世界どうしの適合と移行を支援する。

AI は開発のアシスタントであり、無制限の権限を持つ管理者ではありません。

中核アーキテクチャ、セキュリティ、プレイヤーデータ、正式リリースに関わる変更は、プロジェクトのガバナンスとレビューの手続きに従います。

### 5. あらゆる技術選択は再検討できる

ゲームエンジンは永久ではありません。

SDK も永久ではありません。

世界プロトコルも永久ではありません。

プロジェクトの憲章さえ、永久ではありません。

その時点で有効なガバナンス手続きに従う限り、コミュニティは変更を提案し、審議し、実施することができます。

ある技術が最初に使われたというだけの理由で、未来のすべての創り手にそれへの服従を求めることはしません。

**道具は創造に仕えるべきであって、創造を縛るものであってはなりません。**

## 🪐 ひとつの宇宙、無数の世界

Gateworlds は拡張可能な世界の体系を築くことを目指します。

```text
                  Gateworlds
                      |
              共有宇宙サービス
                      |
       +--------------+--------------+
       |              |              |
    田園世界        修仙世界      サイバー世界
       |              |              |
  コミュニティ   コミュニティ    コミュニティ
    コンテンツ     コンテンツ      コンテンツ

              +-------+
              |
          新しい世界……
```

世界ごとに独自のルール、マップ、セーブデータ、遊び方を持てます。

共有宇宙サービスが担うのは必要最小限——アイデンティティ、世界の発見、転送、世界をまたぐ協働だけです。

世界をまたぐアイテムや能力は、行き先の世界のルールに従わなければなりません。

たとえば修仙世界の飛剣は、田園世界では装飾として存在できますが、他のプレイヤーの建築を壊す権限まで自動的に得てよいわけではありません。

こうした相互運用の機能は段階的に開発するものであり、最初のバージョンですべて実現するものではありません。

## 🛠️ World SDK：誰もが世界を創れるように

創り手がモジュール的に新しい世界を作り、接続できるよう、World SDK の開発を計画しています。

SDK は順次、次のものを提供していきます。

* 世界の登録と読み込み。
* 世界の入口と転送。
* 世界ごとに独立したデータとセーブ。
* 世界間の通信。
* リソースとアイテムの識別子。
* 権限管理。
* バージョン互換性と移行。
* 自動テストとリリースの手順。

SDK 自体も、コミュニティが変更できるプロジェクトの一部です。

既存の SDK が新しい遊び方を支えられないなら、コミュニティは拡張・修正・さらには置き換えを提案できます。

最初の段階で、いわゆる完璧な汎用 SDK を設計しようとはしません。

第一段階では小さな世界を実際にいくつか作り、そこからインターフェースを立ち上がらせます。

## 📜 Gateworlds 憲章

Gateworlds は、公開され、透明で、改正可能なコミュニティ統治の仕組みを段階的に築くことを目指します。

最初の憲章草案では、次の原則を扱います。

**開かれた創造**

誰もがアイデア、開発案、改善提案を出せる。

**公開された統治**

共有宇宙全体に影響する決定は、明確で追跡可能な手続きに従う。

**技術は変更できる**

ゲームエンジン、SDK、中核プロトコル、技術アーキテクチャは、いずれも適用される手続きによって変更できる。

**既存の成果の保護**

大きなアップグレードは、既存の世界、プレイヤーデータ、貢献者の成果を考慮し、妥当な互換性・移行・ロールバックの道を用意する。

**憲章は改正できる**

コミュニティは、その時点で有効な改正手続きに従って憲章を改正できる。改正手続きそのものも含む。

**独立した派生**

採用したライセンスの範囲で、どのような改変・再配布・独立運用が認められるかをプロジェクトは明示する。

コミュニティ統治の体制が整うまでの間、創設メンテナーがプロジェクトの立ち上げ、セキュリティレビュー、リリースを暫定的に担います。

これは恒久的な権力ではありません。

プロジェクトは、明確なメンバーシップ、意思決定手続き、権限の移譲、紛争解決の仕組みを段階的に整える必要があります。

ガバナンス文書は別途管理します。

[`CONSTITUTION.md`](CONSTITUTION.md)

現在の憲章はまだ草案段階であり、具体的な議決方式は未定です。

## 🎮 最初の遊べるバージョン

### Gateworlds 0.0.1

**ここまでは、もう動きます。** `godot --path client-godot` —— 村から東へ歩いてポータルに入り、霊草を拾って戻ってくる。`I` で持ち物、`F5` でセーブ、`F9` でロード。[`docs/BOOTSTRAP.md`](docs/BOOTSTRAP.md) を参照。

最初の開発目標はこれでした。

**村がひとつ、修仙世界がひとつ、ポータルがひとつ。**

第一段階で実装を計画しているもの。

* プレイヤーが初期の村を自由に移動できる。
* プレイヤーがポータルを通って修仙世界へ入れる。
* プレイヤーが修仙世界で霊草を一株入手できる。
* 村へ戻ってもそのアイテムを持ち続けている。
* 両方の世界のデータが正しく読み込み・保存される。
* 世界が初歩的なモジュール構造を持つ。

これを土台に、新しい貢献者が AI を使って三つ目の世界を作り、レビューを経てゲームに接続する、という試みに進みます。

最初のバージョンは、広大なマップや複雑な内容を目指しません。

証明すべきことはひとつだけです。

**新しい世界は本当に創られ、この宇宙に加われるのか。**

初期プロトタイプは開発の複雑さを抑えるため 2D・シングルプレイになる見込みです。これは将来のゲームの次元、表現、マルチプレイ機能に対する恒久的な制約ではありません。

## 🤝 参加するには？

あらゆる形の貢献を歓迎します。

できること。

**アイデアを出す**

新しい世界、新しい遊び方、新しい宇宙のルールを設計する。

**開発に加わる**

AI を使って、あるいは手で書いて、コードを提出する。

**コンテンツを作る**

権利上問題のないマップ、建築、アート、音楽、物語を提供する。

**ゲームをテストする**

バグを探し、性能の問題や遊び心地の問題を報告する。

SDK、プロトコル、サーバー、開発ツールの改善案を出す。

**統治に参加する**

[`CONTRIBUTING.md`](CONTRIBUTING.md) から始めてください。短く、そのままコピーできる完全な世界が載っています。

コードの貢献は Pull Request で提出し、レビューを受けてください。

ライセンスの確認できない第三者のコード、ゲーム素材、個人情報をそのまま提出しないでください。

未選別の AI 生成コンテンツを大量に、正式ブランチへ直接入れることも避けてください。

規約は [`CONTRIBUTING.md`](CONTRIBUTING.md) に、規約についての規約は [`CONSTITUTION.md`](CONSTITUTION.md) にあります。

## 🔒 セキュリティと品質

開かれた創造は、無制限の権限を開くことではありません。

多層のレビューを計画しています。

1. 静的なコード・依存関係の検査。
2. AI 支援によるコードレビュー。
3. 自動の機能テストと互換性テスト。
4. 必要に応じた人間のメンテナーによるレビュー。
5. 隔離されたビルド・テストと段階的リリース。

承認されていない外部コードを、正式なゲームサーバー上で直接実行させてはなりません。

中核システム、プレイヤーのセーブデータ、機微なデータには、より厳格なアクセス制御が必要です。

AI によるレビューは、セキュリティ検査のすべてを代替できません。

リスクの高い変更については、実行環境とプレイヤーデータの保護を優先します。

## 🌱 ゼロから

Gateworlds はまだ、始まったばかりのプロジェクトにすぎません。

すでに築かれた巨大な宇宙はありませんし、AI が開発上のあらゆる問題を自動的に解決すると約束するつもりもありません。

その先は、より多くの創り手が加わり、この宇宙の未来を決める権利を少しずつ手にしていくことです。
